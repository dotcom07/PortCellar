# Korean Windows run observations, 2026-10-11

## Inputs and method

- Host: macOS 26.6.2 (25G83), Apple Silicon; Unity identified Apple M4 Pro.
- Game: publisher Korean configuration version 41.0.1, Unity 2021.3.39f1.
- Game executable SHA-256:
  `f7f2fc9edde3787c33ba24f9bdf4960a3dca798852ff3db17ddd50e20dd47904`.
- Runtime: Arknights macOS Runtime 0.6.1, Wine 11.17,
  DXMT 0.80-244-g7c8dee1, as pinned by the
  [reference client](https://github.com/LuMiSxh/Arknights-MacOS-Client/tree/aa3a8ed7d76d18c9df9ece55026f143f0b98ba1e).
- Runtime archive SHA-256:
  `56e5d3448ad18446b824ec1f7eda266f836bdd3d05b99dcadc0c69a9c0a1dc6d`.
- Managed standalone `wine-dxmt` profile; no Vuplex or PlatformProcess helper
  replacements. PortCellar placed architecture-selected DXMT DLLs beside the
  staged executable, preserving the publisher source directory.

The reference distribution exposes Wine through a symlink. A private shell
adapter invoked the original executable at its original library location, with
the sibling wineserver retained. Copying that executable into `bin` had failed
because Wine then looked for `ntdll.so` there; the distribution's original
symlink was restored. This experiment does not establish turnkey runtime
packaging or a complete runtime dependency fingerprint.

## Installer, launcher, and game are separate results

The supplied official `Arknights_KR_Gamelauncher-1.8.1-setup.exe` had SHA-256
`18b9c02eeb9d6bc04cb941bf52f6908d1a419ad664523f863d479daed1cbf745`.
Static package inspection identified an NSIS wrapper invoking a custom 32-bit
Electron installer with generated local IPC arguments. `/S` did not establish
installation completion. Wine 11.0 returned an installer error; the selected
Wine 11.17 baseline and an MSYNC-only comparison timed out during prefix
initialization. Adding `WINEDLLOVERRIDES=mscoree,mshtml=` to the MSYNC comparison
allowed initialization to finish and the Electron installer to start, but the
installer run still timed out without the requested installation output. This
comparison does not isolate which of those two DLL settings resolved the wait.

The separately extracted official launcher ran in another managed installation.
Its log recorded application readiness and a successful update response for
launcher 1.8.1. Its foreground test timed out. A visible launcher UI and completed
installation/update workflow were not verified.

The game was obtained separately using the publisher manifest/API protocol
documented by the reference client, with TLS validation enabled. All 3,202 files
(3,809,348,105 bytes) matched manifest sizes and CRC64/XZ values before execution.
Local SHA-256 inventory was also retained. This was a private investigation
script, not an implemented PortCellar download command.

Unity logged Direct3D 11.0, feature level 11.1, the M4 Pro graphics device, input
initialization, and the splash controller. The user reported a visible game
window. The first game session subsequently completed with exit code 0 and a
stopped Wine server. These observations do not establish login or gameplay.

## Windowed launch

After server quiescence was confirmed, only the local installation's captured
launch arguments were changed, with the prior binding retained. The existing
game copy and prefix were reused. The arguments were:

```text
-logFile L:\unity-windowed.log -screen-fullscreen 0 -screen-width 1280 -screen-height 720
```

The reference client's `GameLaunchOptions.playerArguments` uses these Unity
display arguments. The user confirmed that this second launch worked in windowed
mode. It was started as a foreground session with a 3,600-second per-subprocess
limit. The shipped module profile retains its original display defaults;
this experiment did not add a profile-edit command or force other installations
to use this resolution.

## Remaining scenarios

Login/browser interactions, notices, audio/video, a playable stage, extended
sessions, and publisher updates remain unverified. Raw logs, screenshots, game
files, account state, private bindings, and the download script remain in ignored
local state. No game or runtime files were published.
